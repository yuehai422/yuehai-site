###### 按场景推荐的impeccable命令流

下面是可直接套用的流程，按你现在这种前端页面迭代场景来排。

1) 新页面从 0 到 1（需求到落地）

teach（仅首次或上下文缺失时）

shape [feature/page]（先定结构、信息层级、交互）

craft [feature/page]（按方案实现）

harden [target]（补错误态、空态、i18n、边界）

polish [target]（视觉和交互收口）

适用：新功能页、新活动页、新模块首版。

2) 旧页面提质（你现在最常用）

critique [target]（先找问题并排序）

layout [target]（先把结构和节奏理顺）

typeset [target]（提升可读性和层级）

clarify [target]（修正文案、按钮、提示语）

polish [target]（最后统一细节）

适用：已有页面“能用但不高级/不清晰”。

3) 页面太素、缺品牌感

bolder [target]（提升视觉张力）

colorize [target]（建立更明确的配色策略）

delight [target]（加入记忆点）

polish [target]（防止“花但乱”）

适用：看起来“模板味重”、缺识别度。

4) 页面太吵、信息过载

quieter [target]（先降噪）

distill [target]（只保留核心表达）

layout [target]（重建阅读路径）

typeset [target]（降低认知负担）

polish [target]

适用：视觉冲突多、用户不知道先看哪里。

5) 上线前质量闸门（发布前必过）

audit [target]（a11y / 响应式 / 性能）

optimize [target]（修关键性能瓶颈）

adapt [target]（多端收口）

harden [target]（边界和异常补齐）

polish [target]

适用：提测前、发版前、验收前。

6) 首次使用/冷启动体验优化

onboard [target]（首屏引导、空状态、激活路径）

clarify [target]（关键提示语和行动文案）

harden [target]（异常分支覆盖）

polish [target]

适用：注册后首用、功能第一次进入、低留存入口。

7) 动效专项（只改 motion 不大改结构）

animate [target]（加入有目的动效）

optimize [target]（检查动效性能）

polish [target]（统一时序与手感）

适用：页面“静态生硬”、交互反馈弱。

8) 高强度创意探索（概念稿/视觉突破）

overdrive [target]（先拉高上限）

distill [target] 或 quieter [target]（回收可用部分）

adapt [target]（落地到真实设备）

polish [target]

适用：活动页、品牌页、需要“惊喜感”的场景。

实操建议（最省事）

首次接入项目先跑一次：teach

大多数页面改版用这条“通用五步流”：

critique -> layout -> typeset -> clarify -> polish

发版前固定补一条：

audit -> optimize -> adapt -> harden -> polish
